# 编码器依赖缓存与增量复用

日期：2026-11-17。

本次实现编码器缓存接口并接入原生 Qwen 流。缓存以单个识别流为生命周期，
关闭、取消、重新打开流时释放；固定提示 KV 仍按模型生命周期保留。
没有改变模型的注意力范围、Mel 归一化或现有 3 秒最大段长。

## 支持范围

| 场景 | 复用范围 | 重算范围 |
|---|---|---|
| 归一化 Mel 完全相同、长度相同 | 完整编码器最终输出 | 无 |
| 默认整段双向注意力，追加或修改 Mel | 未变化块的三层卷积、投影、位置编码 | 整个区域的所有注意力层、FFN 和末端投影 |
| 已有独立窗口注意力 | 未变化独立窗口的完整编码结果，及其他未变化的卷积块 | 修改的窗口和增长中的尾部窗口 |
| 后续更大音量改变历史 Mel 归一化 | 仅字节仍相同的块/区域 | 所有发生变化的依赖区域 |

完整缓存**不能等同于默认模型全层只计算新增音频**。默认 Qwen 编码器使用双向注意力，
新音频会改变历史帧的逐层输出，冻结历史 K/V 会改变识别结果。
本实现按依赖关系失效，保持全量计算语义，不通过冻结旧帧或修改注意力掩码伪造命中。

已有窗口模式通常以 8 秒为独立窗口；当前服务默认每段最多 3 秒，
因此服务主要受益于卷积复用，通常没有完整的历史注意力窗口可以复用。
只在已经启用窗口注意力的模型/运行方式中复用独立窗口，本次不自动切换该模式。
窗口模式与默认双向模式之间的跨模式准确率不属于本次缓存一致性结论。

## 实现

- `crisp_audio_encoder_cache_*` 管理缓存，`crisp_audio_encode_cached` 执行依赖检查和复用。
- `core/audio_encoder_cache.h` 保存归一化 Mel 块、卷积快照和独立区域最终输出。
- 比较归一化 Mel 的实际字节，处理全局裁剪阈值变化、尾部反射 padding 和不完整卷积块。
- 模型上下文、padding 模式或窗口模式变化时清空缓存；长度缩短时删除过期块和区域。
- 没有命中时仍执行原有完整图，只增加独立的卷积输出快照，避免额外分成两次计算。
- 快照使用独立复制分支并标为输出，防止后续原地计算覆盖，绝不跨调用保存 ggml 图指针或设备缓冲句柄。
- 命中卷积块时仅计算缺失块，再将完整卷积序列送入受影响的注意力区域。
- 开启 `CRISP_AUDIO_DUMP_STAGES` 时执行原有完整计算和中间张量导出，保留诊断行为。
- 缓存只保留当前输入长度对应的数据，服务的活动段上限继续约束内存占用。

`CRISPASR_QWEN3_STREAM_PROFILE=1` 输出新增：
`stem_reused`、`stem_computed`、`encoder_regions_reused`、`encoder_regions_computed`、
`encoder_window_chunks`、`encoder_cached_bytes`。这些是当前实际调用的数量，
不会把双向注意力重算误报为完整编码器命中。

在进程启动前设置 `CRISPASR_QWEN3_STREAM_ENCODER_CACHE=0` 可关闭此缓存，
固定提示 KV 复用和其他调度行为不变。

## 验证

无模型的 QTest 验证以下依赖规则：双向追加失效、独立窗口复用、全局归一化变化、
长度变化但零填充字节相同、长度缩短、模式变化、清空与非法参数。

模型测试使用本地 Qwen3-ASR-0.6B Q4_K，CPU 2 线程，分别比较默认双向、
保留 padding 的兼容模式和已有窗口模式。测试长度覆盖 99/100/101 Mel 帧，
799/801/820/901 帧、不完整尾部、相同输入重复调用和缩短输入。
本机所测张量最大绝对误差和相对 RMS 误差均为 0；测试阈值为相对 RMS < 1e-4、
最大绝对误差 < 0.005。
窗口模式从 801 增长至 820 帧时，验证完整复用第一个窗口，只重算增长的尾部窗口。

真实 PCM 测试覆盖 0.5/1/1.5/2/3 秒累计语音、后半段突然增大的声音，
识别文字与不使用编码器缓存时一致。原生 C ABI 流逐次比较所有预览和最终文本，
覆盖关闭、重新打开、取消未完成流后重录，结果一致。另验证同一模型切换注意力模式，
以及将缓存交给另一模型上下文后自动失效。
本次未做新中文语料 CER 评估，也未验证实际 GPU 设备。

## A/B 数据

Intel Core i7-10700，2 线程，RelWithDebInfo，Qwen3-ASR-0.6B Q4_K。
以 Korean 提示识别 `ko-369.wav`，两份独立模型上下文都预热并保留固定提示 KV，
唯一测量差异为编码器缓存开关。累计输入按 0.5/1.5/3 秒增长，
5 轮，每轮重置编码器缓存并交替 A/B 执行顺序，共 15 组配对调用。
音频加载和哈希计算不计入推理耗时。

| 累计音频 | 全量编码中位耗时 | 缓存编码中位耗时 | 全量总耗时 | 缓存总耗时 | 复用卷积块中位数 |
|---|---:|---:|---:|---:|---:|
| 500ms | 124.0ms | 123.9ms | 391.5ms | 384.4ms | 0 |
| 1500ms | 256.8ms | 254.2ms | 808.5ms | 817.0ms | 0 |
| 3000ms | 435.5ms | 369.4ms | 1215.5ms | 1140.6ms | 1 |

每组文字和生成 token 数相同。3 秒样本复用了一个历史卷积块，编码阶段约下降 15%，
总耗时约下降 6%；短输入未稳定命中，总耗时基本持平。
混合长度总耗时的中位数没有改善，不能声称所有输入或端到端延迟都会下降。
独立窗口缓存的正确性由长输入张量测试验证，此表不包含窗口模式收益。
原始分阶段数据、CPU/模型/音频身份和每组结果哈希见同名 JSON。
这些是本机缓存 A/B 数据，不是版本发布性能门禁证据。

## 复现

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build -j4
ctest --test-dir build --output-on-failure
ECHOFLOW_QWEN3_TEST_MODEL=/path/to/qwen3-asr-0.6b-q4_k.gguf \
  ./build/tests/test_encoder_cache
./build/tests/stream_profile_benchmark --encoder-cache \
  --model /path/to/qwen3-asr-0.6b-q4_k.gguf \
  --wav /path/to/speech.wav --language Korean \
  --threads 2 --repeats 5 --output /tmp/encoder-cache-ab.json
```

真实模型回归还需本地 `third_party/crispasr/samples/ko-369.wav` 夹具。
没有模型时仍运行缓存依赖规则测试，模型用例跳过；不要求采集设备或 Fcitx。
